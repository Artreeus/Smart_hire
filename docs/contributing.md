# Contributing

1. Create a focused branch from `main`.
2. Keep credentials in `.env` and never commit secrets.
3. Make small, descriptive commits.
4. Run `npm run build` and `npm audit` before opening a pull request.
5. Document API or schema changes in `docs/`.
6. Include migration or compatibility notes for model changes.

Code should preserve role authorization, record ownership checks, human control over AI-assisted decisions, and accessible responsive behavior.

Pull requests should describe the problem, implementation, verification performed, screenshots for visual changes, and any deployment impact.
